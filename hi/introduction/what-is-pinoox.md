# Pinoox क्या है?

[← इंडेक्स पर वापस जाएँ](../README.md)

Pinoox एक आधुनिक, ओपन-सोर्स PHP फ्रेमवर्क (3.x) है जो HMVC आर्किटेक्चर और **ऐप** की अवधारणा पर बना है। यह मॉड्यूलर वेब डेवलपमेंट को सरल बनाता है: प्रत्येक ऐप `apps/{package}/` के अंतर्गत एक स्वतंत्र MVC इकाई है, जबकि साझा फ्रेमवर्क कोर `vendor/pinoox/pincore/` में रहता है।

---

## ऐप-केंद्रित आर्किटेक्चर

एक ही Pinoox इंस्टॉलेशन में, कई स्वतंत्र ऐप्स साथ-साथ चलते हैं:

```
{project_root}/
├── index.php              ← वेब एंट्री पॉइंट
├── pinoox                 ← CLI एंट्री पॉइंट
├── composer.json
├── vendor/pinoox/pincore/ ← फ्रेमवर्क कोर (केवल कोर बदलावों के लिए संपादित करें)
└── apps/
    ├── com_pinoox_manager/
    └── com_example_blog/  ← आपका ऐप
```

- **प्रोजेक्ट** — वह फ़ोल्डर जिसमें `index.php` और `apps/` होते हैं (फ़ोल्डर का नाम मायने नहीं रखता)।
- **ऐप** — अपने नियंत्रकों (controllers), मॉडल (models), मार्गों (routes), थीम और कॉन्फ़िग (config) के साथ एक पूर्ण मॉड्यूल।
- **कोर** — साझा इंजन (Router, HTTP, डेटाबेस, Twig, CLI आदि)।

बिज़नेस लॉजिक `apps/` में लिखें, `vendor/pinoox/pincore/` में नहीं।

---

## HTTP अनुरोध का जीवनचक्र

```
ब्राउज़र → index.php → बूटस्ट्रैप
        → सक्रिय ऐप का निर्धारण (डोमेन या URL उपसर्ग)
        → app.php और routes/ लोड करना
        → Flows → Controller → Model (वैकल्पिक) → View या JSON
```

---

## ऐप का नामकरण

अनुशंसित पैकेज प्रारूप:

```
com_{vendor}_{name}
```

उदाहरण: `com_acme_shop` — फ़ोल्डर का नाम, `app.php` में `package` मान, और namespace खंड — सभी का मेल खाना आवश्यक है।

---

## इनके लिए उपयुक्त

- मल्टी-सेक्शन साइटें और एडमिन पैनल जहाँ प्रत्येक सेक्शन एक अलग ऐप हो सकता है
- ऐसी टीमें जो मॉड्यूल्स को स्वतंत्र रूप से विकसित, टेस्ट और मेंटेन करना चाहती हैं
- Composer और एकीकृत CLI (`php pinoox …`) के साथ PHP 8.1+ प्रोजेक्ट्स
