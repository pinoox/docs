# Что такое Pinoox?

[← Вернуться к оглавлению](../README.md)

Pinoox — это современный PHP-фреймворк с открытым исходным кодом (3.x), построенный на архитектуре HMVC и концепции **приложений (app)**. Он делает модульную веб-разработку простой: каждое приложение — это независимый MVC-модуль в `apps/{package}/`, а общее ядро фреймворка находится в `vendor/pinoox/pincore/`.

---

## Архитектура, ориентированная на приложения

В одной установке Pinoox несколько независимых приложений работают бок о бок:

```
{project_root}/
├── index.php              ← веб-точка входа
├── pinoox                 ← точка входа CLI
├── composer.json
├── vendor/pinoox/pincore/ ← ядро фреймворка (изменяйте только для правок ядра)
└── apps/
    ├── com_pinoox_manager/
    └── com_example_blog/  ← ваше приложение
```

- **Проект (Project)** — папка, содержащая `index.php` и `apps/` (имя папки не имеет значения).
- **Приложение (App)** — полноценный модуль со своими контроллерами, моделями, маршрутами, темой и конфигурацией.
- **Ядро (Core)** — общий движок (роутер, HTTP, база данных, Twig, CLI и многое другое).

Пишите бизнес-логику в `apps/`, а не в `vendor/pinoox/pincore/`.

---

## Жизненный цикл HTTP-запроса

```
Браузер → index.php → инициализация (bootstrap)
       → определение активного приложения (домен или префикс URL)
       → загрузка app.php и routes/
       → Flows → Controller → Model (по желанию) → View или JSON
```

---

## Именование приложений

Рекомендуемый формат имени пакета:

```
com_{vendor}_{name}
```

Пример: `com_acme_shop` — имя папки, значение `package` в `app.php` и сегмент пространства имён должны совпадать.

---

## Хорошо подходит для

- Многосекционных сайтов и админ-панелей, где каждый раздел может быть отдельным приложением
- Команд, которые хотят разрабатывать, тестировать и сопровождать модули независимо
- Проектов на PHP 8.1+ с Composer и встроенным CLI (`php pinoox …`)
